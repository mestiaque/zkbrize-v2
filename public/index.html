1 Getting Started

The bridge sits between your ZKTeco attendance devices and your ERP / HRM / payroll system. It sends employees to the devices, collects every punch, and pushes the punches to the ERP.

First run

1
Open the bridge in a browser. On a new installation the Setup wizard opens: it checks the computer, creates the administrator account, optionally connects the ERP, and sets the app name and the ADMS port.
2
Sign in. Choose the interface language with the EN | বাং switch in the top bar (also on the sign-in page). The choice is remembered on this browser.

Five steps to a working bridge

1
Settings → ERP API Configuration: enter the ERP API Base URL and token, click Test Connection.
2
Connect devices: ADMS devices point to port (section 3); older devices are added by IP on Devices (section 4).
3
Employees → Load from ERP, then Set to Device.
4
Punches appear on Attendance as they happen.
5
Turn on Attendance Push in Settings so new punches go to the ERP automatically.
The top bar shows the live date and time, the server connection (Live / Disconnected) and the Sync Now button.
2 Dashboard
Present / Late / Absent todayCounted from each employee's first punch today. Late = after the start time plus grace period (Settings → Attendance Rules). Absent needs employees in the bridge.
Waiting for ERPPunches not yet accepted by the ERP.

Late arrivals todayWho was late and by how many minutes.

Connected Devices, Recent Activity, Sync HistoryDevice status, the latest punches and the latest sync results.
3 ADMS (push) Devices

Newer ZKTeco devices (ADMS / Cloud Server / iClock) send punches to the bridge by themselves, in real time. On the device open Menu → COMM → Cloud Server Setting (older models: Comm → ADMS):

FieldValueNote
Server ModeADMSIf the device offers it
Enable Domain NameOFFUse the IP address
Server AddressThis computer's LAN IP
Server PortSettings → ADMS Server Info
HTTPS / ProxyOFF

Save and restart the device. Within a minute it appears on Devices and the Logs show ADMS handshake. Name and employee changes reach ADMS devices on their next check-in (about 30 seconds). Use Attendance → Fetch ADMS to ask the device for punches it stored before it was connected.

Never enter localhost or 127.0.0.1 on a device. Give this computer a fixed IP and allow port in its firewall.
4 TCP/IP (pull) Devices

Older devices without ADMS are read by the bridge over the network (port 4370). Each read opens a short session: connect, pause the device, read, resume, disconnect.

1
Give the device a fixed IP (Menu → COMM → Ethernet, DHCP off) or reserve its IP in the router.
2
On Devices, check it with Network Ping Test.
3
Add TCP/IP Device: IP, port 4370, a name, and the Comm Key if the device has one (Menu → COMM → PC Connection → Comm Key). Click Connect Device.
4
Punches are read with every scheduled Attendance Push, with Sync Now, with Attendance → Fetch TCP, or with the device's Fetch button.

Device list buttons

FetchRead this device's punches now.
Sync EmpLoad employees from the ERP and write them to this device.
EditChange IP, port, name or Comm Key. The device keeps its ID and records. Leave Comm Key empty to keep it; 0 means none.
DisconnectRemove the device from the bridge. Its records stay.
Good to know: devices are remembered across restarts. If a device was offline it shows error and is tried again on the next sync. If a device's IP changed, just add it again with the new IP: the bridge recognises it by its serial number and updates the old entry, so no punch is sent to the ERP twice. Without a date range, a fetch takes the last retention period (90 days by default); use From / To on Attendance to fetch older punches.
5 Employees
Load from ERPImports employees from the ERP and saves them in the bridge.
Load from MachineReads the users stored on a device (asks which device when several are connected).
Set to DeviceSends employees that are Not Synced to every connected device. ADMS devices apply them on their next check-in.
+ Add Employee / Edit / DeleteCreate, change or remove one employee; the change goes to connected devices right away.
Search & filterBy name, employee ID, UID, and Synced / Not Synced.
⬇ CSVFor ZKBio Security / ZKTime.Net desktop software.
⬇ DATuser.dat for USB import: on the device Menu → USB Manager → Upload → User Info.

Fields

  • UID — the device's user slot, unique per employee.
  • Employee ID — the ID shown on the device and sent to the ERP with each punch.
  • Role — User or Admin (an admin can open the device menu).
  • Password / PIN — optional, up to 8 digits.

An employee is marked Synced only after a device accepted them; the rest are tried again on the next sync.

6 Attendance

Every punch from every device, newest first. New = not yet accepted by the ERP; Pushed = accepted (shown faded, with the time it was sent).

From / ToShows records in that date range, and limits Fetch TCP / Fetch ADMS to it.
Fetch TCPReads all TCP/IP devices now.
↓ Fetch ADMSAsks ADMS devices to upload stored punches (all history, or the date range). They arrive within about 10 seconds.
Push to ERPSends every New record to the ERP now.
FiltersEmployee ID, date, device, type (Check In / Out), method (face, fingerprint, card, password), source (ADMS / TCP), status (New / Pushed).

Punch types: 0 Check-In, 1 Check-Out, 2 Break-Out, 3 Break-In, 4 OT-In, 5 OT-Out. The same punch is never stored twice.

9 Users, Roles & Permissions

Administration → Users & Roles (owner only): add users, set their role and password. Built-in roles: superadmin (everything), admin, viewer. Make your own roles and switch on exactly the pages and buttons each may use.

Administration → Interface Permissions: turn pages and buttons off for everyone at once. A feature is available only when both this page and the user's role allow it. The server enforces the same rules, so a hidden button cannot be used through the API either.

Lost the admin password? Set MASTER_USERNAME and MASTER_PASSWORD in .env, restart, sign in with them and reset the password. Then clear both values again.
10 ERP API

Your ERP needs three JSON endpoints under the API Base URL. With a token set, every request carries Authorization: Bearer <token>.

MethodPathPurpose
GET/zk/pingConnection test — any 2xx response
GET/zk/employeesEmployees for the devices
POST/zk/attendanceReceives punches

GET /zk/employees — response

{ "data": [
  { "uid": 1, "employee_id": "1001", "name": "Ayesha Rahman", "privilege": 0, "password": "" }
] }

POST /zk/attendance — request body

{ "records": [
  { "employeeId": "1001", "time": "2026-10-10 08:42:04", "status": "0",
    "deviceId": "CQZ7224460123", "source": "adms", "verifyMethod": "fingerprint" }
] }
uidDevice user slot, unique per employee
employee_id / employeeIdThe ID employees use on the device
privilege0 user, 14 admin
statusPunch type, see section 6
timeDevice local time, YYYY-MM-DD HH:MM:SS
sourceadms or tcp
Reply with any 2xx status (optionally { "saved": 12 }). Otherwise the records stay New and are sent again next time — so treat employeeId + time + deviceId as unique and ignore duplicates.
11 Logs, Data & Backup

Logs shows the server's activity: device handshakes, fetches, pushes and errors. Clear Logs empties the log and the sync history.

Everything is stored in the data/ folder next to the app:

attendance.jsonPunches (kept for the retention period; records not yet sent to the ERP are always kept)
employees.jsonEmployees
tcp-devices.jsonTCP/IP devices and their Comm Keys
users.json, roles.json, permissions.jsonSign-in accounts and permissions
config.json, branding.jsonSchedules, rules and branding (ERP URL/token and ports are in .env)
To back up, copy the data/ folder and the .env file. When updating the app, keep both — never overwrite them with a fresh copy.
12 Troubleshooting
ProblemWhat to check
ADMS device does not appearServer address and port on the device, the firewall, same network (Ping Test). Restart the device and watch Logs for ADMS handshake.
TCP: "Connection refused"Wrong port, or TCP communication is off on the device. Default port is 4370.
TCP: "timed out" / "unreachable"Wrong IP, device off, or another network. Run the Ping Test.
TCP: "rejected the comm key"Enter the device's Comm Key (Menu → COMM → PC Connection), or 0 if it has none.
Device IP changedAdd it again with the new IP (matched by serial number), or use Edit.
Test Connection fails401/403: wrong token. 404: wrong base URL (include /api if your routes use it).
Records stay "New"Turn on Attendance Push, click Push to ERP and read the message and Logs.
Older punches are missingSet From / To on Attendance, then Fetch TCP or Fetch ADMS.
Employee not on the deviceCheck the employee shows Not Synced, click Set to Device, and wait 30 seconds for ADMS devices.
Web page does not open from another PCAllow the web port (default 3000) in the firewall; HOST in .env must be 0.0.0.0.

১ শুরু করা

ব্রিজটি আপনার ZKTeco হাজিরা ডিভাইস আর ERP / HRM / পেরোল সিস্টেমের মাঝে কাজ করে। এটি কর্মীর তালিকা ডিভাইসে পাঠায়, প্রতিটি পাঞ্চ সংগ্রহ করে, এবং সেগুলো ERP-তে পাঠায়।

প্রথমবার চালানো

১
ব্রাউজারে ব্রিজটি খুলুন। নতুন ইনস্টলেশনে সেটআপ উইজার্ড খুলবে: এটি কম্পিউটার যাচাই করে, অ্যাডমিন অ্যাকাউন্ট তৈরি করে, চাইলে ERP যুক্ত করে, এবং অ্যাপের নাম ও ADMS পোর্ট ঠিক করে।
২
সাইন ইন করুন। উপরের বারের EN | বাং বোতাম দিয়ে ভাষা বেছে নিন (সাইন ইন পেজেও আছে)। এই ব্রাউজারে আপনার পছন্দ মনে রাখা হবে।

পাঁচ ধাপে চালু করুন

১
সেটিংস → ERP API কনফিগারেশন: ERP API বেস URL ও টোকেন দিয়ে সংযোগ পরীক্ষা চাপুন।
২
ডিভাইস যুক্ত করুন: ADMS ডিভাইসে সার্ভার , পোর্ট দিন (অংশ ৩); পুরোনো ডিভাইস ডিভাইস পেজ থেকে IP দিয়ে যোগ করুন (অংশ ৪)।
৩
কর্মী → ERP থেকে লোড, তারপর ডিভাইসে পাঠান।
৪
পাঞ্চ হওয়ার সাথে সাথে হাজিরা পেজে দেখা যাবে।
৫
সেটিংসে হাজিরা পাঠানো চালু করুন, যাতে নতুন পাঞ্চ নিজে থেকেই ERP-তে যায়।
উপরের বারে চলমান তারিখ ও সময়, সার্ভারের সাথে সংযোগ (লাইভ / সংযোগ বিচ্ছিন্ন) এবং এখনই সিঙ্ক বোতাম থাকে।
২ ড্যাশবোর্ড
আজ উপস্থিত / দেরিতে / অনুপস্থিতআজ প্রত্যেক কর্মীর প্রথম পাঞ্চ থেকে গোনা হয়। দেরি = শুরুর সময় আর ছাড়ের সময়ের পরে (সেটিংস → হাজিরার নিয়ম)। অনুপস্থিত গুনতে ব্রিজে কর্মী থাকতে হবে।
ERP-তে পাঠানো বাকিযে পাঞ্চ এখনো ERP গ্রহণ করেনি।
গত ৭ দিনপ্রতিদিন সময়মতো ও দেরিতে আসা কর্মী।
আজ দেরিতে আসাকে দেরি করেছেন এবং কত মিনিট।
ঘণ্টা অনুযায়ী আগমন, যাচাইয়ের পদ্ধতি, ডিভাইস অনুযায়ী পাঞ্চকখন আসেন, কীভাবে যাচাই হয় (ফিঙ্গার, ফেস, কার্ড, পাসওয়ার্ড) এবং কোন ডিভাইস ব্যবহার হয়।
সংযুক্ত ডিভাইস, সাম্প্রতিক কার্যকলাপ, সিঙ্ক ইতিহাসডিভাইসের অবস্থা, সর্বশেষ পাঞ্চ ও সর্বশেষ সিঙ্কের ফল।
৩ ADMS (push) ডিভাইস

নতুন ZKTeco ডিভাইস (ADMS / Cloud Server / iClock) নিজে থেকেই রিয়েল-টাইমে ব্রিজে পাঞ্চ পাঠায়। ডিভাইসে Menu → COMM → Cloud Server Setting খুলুন (পুরোনো মডেলে Comm → ADMS):

ঘরমানমন্তব্য
Server ModeADMSডিভাইসে থাকলে
Enable Domain NameOFFIP ঠিকানা ব্যবহার করুন
Server Addressএই কম্পিউটারের LAN IP
Server Portসেটিংস → ADMS সার্ভারের তথ্য
HTTPS / ProxyOFF

সংরক্ষণ করে ডিভাইস রিস্টার্ট দিন। এক মিনিটের মধ্যে এটি ডিভাইস পেজে আসবে এবং লগে ADMS handshake দেখা যাবে। নাম ও কর্মীর পরিবর্তন ADMS ডিভাইস পরের check-in-এ (প্রায় ৩০ সেকেন্ড) নেয়। সংযোগের আগে ডিভাইসে জমা পাঞ্চ আনতে হাজিরা → ADMS থেকে আনুন ব্যবহার করুন।

ডিভাইসে কখনো localhost বা 127.0.0.1 দেবেন না। এই কম্পিউটারকে স্থায়ী IP দিন এবং ফায়ারওয়ালে পোর্ট খুলে দিন।
৪ TCP/IP (pull) ডিভাইস

ADMS নেই এমন পুরোনো ডিভাইস ব্রিজ নিজে নেটওয়ার্ক দিয়ে পড়ে (পোর্ট 4370)। প্রতিবার পড়ার সময় একটি ছোট সেশন খোলে: সংযোগ, ডিভাইস কিছুক্ষণ থামানো, পড়া, আবার চালু, সংযোগ বন্ধ।

১
ডিভাইসকে স্থায়ী IP দিন (Menu → COMM → Ethernet, DHCP বন্ধ) অথবা রাউটারে IP রিজার্ভ করুন।
২
ডিভাইস পেজে নেটওয়ার্ক পিং টেস্ট দিয়ে যাচাই করুন।
৩
TCP/IP ডিভাইস যোগ করুন: IP, পোর্ট 4370, একটি নাম, আর ডিভাইসে থাকলে Comm Key (Menu → COMM → PC Connection → Comm Key)। ডিভাইস সংযোগ করুন চাপুন।
৪
প্রতিটি নির্ধারিত হাজিরা পাঠানো, এখনই সিঙ্ক, হাজিরা → TCP থেকে আনুন, অথবা ডিভাইসের আনুন বোতামে পাঞ্চ পড়া হয়।

ডিভাইস তালিকার বোতাম

আনুনএখনই এই ডিভাইসের পাঞ্চ পড়ুন।
কর্মী সিঙ্কERP থেকে কর্মী এনে এই ডিভাইসে লিখুন।
এডিটIP, পোর্ট, নাম বা Comm Key বদলান। ডিভাইসের ID ও রেকর্ড একই থাকে। Comm Key খালি রাখলে আগেরটা থাকে; 0 মানে নেই।
সরিয়ে দিনব্রিজ থেকে ডিভাইস সরান। এর রেকর্ড থেকে যায়।
জেনে রাখুন: রিস্টার্টের পরেও ডিভাইসগুলো মনে থাকে। ডিভাইস বন্ধ থাকলে ত্রুটি দেখায় এবং পরের সিঙ্কে আবার চেষ্টা হয়। ডিভাইসের IP বদলে গেলে শুধু নতুন IP দিয়ে আবার যোগ করুন: ব্রিজ সিরিয়াল নম্বর দেখে ডিভাইস চিনে পুরোনোটাই আপডেট করে, তাই কোনো পাঞ্চ ERP-তে দুবার যায় না। তারিখের সীমা না দিলে শুধু রিটেনশন সময়ের (ডিফল্ট ৯০ দিন) পাঞ্চ আনা হয়; আরও পুরোনো পাঞ্চ আনতে হাজিরা পেজে থেকে / পর্যন্ত দিন।
৫ কর্মী
ERP থেকে লোডERP থেকে কর্মী এনে ব্রিজে সংরক্ষণ করে।
মেশিন থেকে লোডডিভাইসে থাকা ইউজার পড়ে (একাধিক ডিভাইস থাকলে কোনটি থেকে, তা জিজ্ঞেস করে)।
ডিভাইসে পাঠানসিঙ্ক হয়নি এমন কর্মীদের সব সংযুক্ত ডিভাইসে পাঠায়। ADMS ডিভাইস পরের check-in-এ নেয়।
+ কর্মী যোগ করুন / এডিট / মুছুনএকজন কর্মী তৈরি, পরিবর্তন বা মুছে ফেলুন; পরিবর্তন সাথে সাথে সংযুক্ত ডিভাইসে যায়।
খোঁজা ও ফিল্টারনাম, কর্মী ID, UID এবং সিঙ্ক হয়েছে / হয়নি অনুযায়ী।
⬇ CSVZKBio Security / ZKTime.Net ডেস্কটপ সফটওয়্যারের জন্য।
⬇ DATUSB দিয়ে ইমপোর্টের জন্য user.dat: ডিভাইসে Menu → USB Manager → Upload → User Info।

ঘরগুলো

  • UID — ডিভাইসে ইউজারের নম্বর, প্রত্যেক কর্মীর আলাদা।
  • কর্মী ID — ডিভাইসে যে ID দেখায় এবং প্রতিটি পাঞ্চের সাথে ERP-তে যায়।
  • রোল — ইউজার বা অ্যাডমিন (অ্যাডমিন ডিভাইসের মেনু খুলতে পারেন)।
  • পাসওয়ার্ড / PIN — ঐচ্ছিক, সর্বোচ্চ ৮ অঙ্ক।

ডিভাইস গ্রহণ করার পরেই শুধু কর্মীকে সিঙ্ক হয়েছে চিহ্ন দেওয়া হয়; বাকিদের পরের সিঙ্কে আবার চেষ্টা হয়।

৬ হাজিরা

সব ডিভাইসের প্রতিটি পাঞ্চ, নতুনগুলো উপরে। নতুন = এখনো ERP গ্রহণ করেনি; পাঠানো হয়েছে = গ্রহণ করেছে (হালকা রঙে, পাঠানোর সময়সহ)।

থেকে / পর্যন্তওই তারিখের রেকর্ড দেখায় এবং TCP / ADMS থেকে আনার সময় ওই সীমায় আনে।
TCP থেকে আনুনএখনই সব TCP/IP ডিভাইস পড়ে।
↓ ADMS থেকে আনুনADMS ডিভাইসকে জমা পাঞ্চ পাঠাতে বলে (সব ইতিহাস বা তারিখের সীমা)। প্রায় ১০ সেকেন্ডে আসে।
ERP-তে পাঠানসব নতুন রেকর্ড এখনই ERP-তে পাঠায়।
ফিল্টারকর্মী ID, তারিখ, ডিভাইস, ধরন (চেক ইন / আউট), পদ্ধতি (ফেস, ফিঙ্গারপ্রিন্ট, কার্ড, পাসওয়ার্ড), উৎস (ADMS / TCP), অবস্থা (নতুন / পাঠানো)।

পাঞ্চের ধরন: 0 চেক-ইন, 1 চেক-আউট, 2 বিরতি শুরু, 3 বিরতি শেষ, 4 ওভারটাইম শুরু, 5 ওভারটাইম শেষ। একই পাঞ্চ কখনো দুবার জমা হয় না।

৭ সিঙ্ক ও সময়সূচি
এখনই সিঙ্ক (উপরের বার)TCP/IP ডিভাইস পড়ে, তারপর সব নতুন রেকর্ড ERP-তে পাঠায়।
কর্মী সিঙ্কসময়সূচি অনুযায়ী: ERP থেকে কর্মী এনে নতুনদের ডিভাইসে পাঠায়।
হাজিরা পাঠানোসময়সূচি অনুযায়ী: TCP/IP ডিভাইস পড়ে, তারপর নতুন রেকর্ড ERP-তে পাঠায়।

সময়সূচি cron ফরম্যাটে, সেটিংস → সিঙ্কের সময়সূচি-তে (বা প্রিসেট বোতামে) ঠিক করা হয়। প্রতিটির চালু/বন্ধ সুইচ আছে।

৮ সেটিংস
ERP API কনফিগারেশনবেস URL (আপনার route-এ থাকলে /api সহ), ঐচ্ছিক Bearer টোকেন, এবং ERP অন্য path ব্যবহার করলে কর্মী আনা ও হাজিরা পাঠানোর পূর্ণ URL। সংযোগ পরীক্ষা /zk/ping-এ কল করে।
সিঙ্কের সময়সূচিকর্মী সিঙ্ক ও হাজিরা পাঠানোর চালু/বন্ধ ও সময়।
ADMS সার্ভারের তথ্যডিভাইস যে ঠিকানা ব্যবহার করবে, এবং ADMS পোর্ট বদলান (সাথে সাথে কার্যকর, রিস্টার্ট লাগে না)। সার্ভার রিস্টার্ট ব্রিজ রিস্টার্ট করে।
হাজিরার নিয়মকাজ শুরুর সময় ও ছাড়ের মিনিট, দেরি গোনার জন্য।
ব্র্যান্ডিং (superadmin)অ্যাপের নাম, ট্যাগলাইন, লোগো, প্রধান রং, ফুটারে কোম্পানির নাম ও ওয়েবসাইট।
৯ ইউজার, রোল ও অনুমতি

প্রশাসন → ইউজার ও রোল (শুধু মালিক): ইউজার যোগ করুন, রোল ও পাসওয়ার্ড দিন। বিল্ট-ইন রোল: superadmin (সব কিছু), admin, viewer। নিজের রোল বানিয়ে ঠিক কোন পেজ ও বোতাম ব্যবহার করা যাবে তা চালু করুন।

প্রশাসন → ইন্টারফেস অনুমতি: সবার জন্য একসাথে পেজ ও বোতাম বন্ধ করুন। এই পেজ এবং ইউজারের রোল দুটোই অনুমতি দিলেই কোনো ফিচার ব্যবহার করা যায়। সার্ভারও একই নিয়ম মানে, তাই লুকানো বোতাম API দিয়েও ব্যবহার করা যায় না।

অ্যাডমিনের পাসওয়ার্ড ভুলে গেছেন? .env-এ MASTER_USERNAME ও MASTER_PASSWORD দিয়ে রিস্টার্ট করুন, সেগুলো দিয়ে সাইন ইন করে পাসওয়ার্ড বদলান। তারপর দুটো মান আবার মুছে দিন।

১১ লগ, ডেটা ও ব্যাকআপ

১২ সমস্যার সমাধান
সমস্যাযা দেখবেন
ADMS ডিভাইস দেখা যাচ্ছে নাডিভাইসে সার্ভার ঠিকানা ও পোর্ট, ফায়ারওয়াল, একই নেটওয়ার্ক কিনা (পিং টেস্ট)। ডিভাইস রিস্টার্ট দিয়ে লগে ADMS handshake খুঁজুন।
TCP: "সংযোগ প্রত্যাখ্যাত"পোর্ট ভুল, বা ডিভাইসে TCP যোগাযোগ বন্ধ। ডিফল্ট পোর্ট 4370।
TCP: "সময় শেষ" / "পাওয়া যাচ্ছে না"IP ভুল, ডিভাইস বন্ধ, বা অন্য নেটওয়ার্ক। পিং টেস্ট চালান।
TCP: "Comm Key গ্রহণ করেনি"ডিভাইসের Comm Key দিন (Menu → COMM → PC Connection), না থাকলে 0।
ডিভাইসের IP বদলে গেছেনতুন IP দিয়ে আবার যোগ করুন (সিরিয়াল নম্বর দিয়ে চিনে নেবে), অথবা এডিট ব্যবহার করুন।
সংযোগ পরীক্ষা ব্যর্থ401/403: টোকেন ভুল। 404: বেস URL ভুল (route-এ থাকলে /api সহ দিন)।
রেকর্ড "নতুন"-ই থেকে যাচ্ছেহাজিরা পাঠানো চালু করুন, ERP-তে পাঠান চেপে বার্তা ও লগ পড়ুন।
পুরোনো পাঞ্চ আসেনিহাজিরা পেজে থেকে / পর্যন্ত দিয়ে TCP বা ADMS থেকে আনুন।
কর্মী ডিভাইসে নেইকর্মীর পাশে সিঙ্ক হয়নি দেখাচ্ছে কিনা দেখুন, ডিভাইসে পাঠান চাপুন, ADMS ডিভাইসের জন্য ৩০ সেকেন্ড অপেক্ষা করুন।
অন্য কম্পিউটার থেকে পেজ খোলে নাফায়ারওয়ালে ওয়েব পোর্ট (ডিফল্ট 3000) খুলুন; .env-এ HOST হতে হবে 0.0.0.0।
