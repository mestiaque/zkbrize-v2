User Guide

Connect devices, link your ERP and fix common problems

Contents
Quick Start ADMS Devices TCP/IP Devices ERP API Daily Use Troubleshooting
1 Quick Start
1
Open Settings, enter your ERP API Base URL and token, and click Test Connection.
2
On each ADMS device, set the server to port (see below). Older devices: add them on the Devices page.
3
On Employees, click Load from ERP, then Set to Device.
4
Punches appear on Attendance in real time. Turn on Attendance Push in Settings to send them to the ERP automatically.
2 ADMS (push) Devices

On the device: Menu → COMM → Cloud Server Setting (older models: Comm → ADMS)

FieldValueNote
Server ModeADMSIf the device offers it
Enable Domain NameOFFUse the IP address
Server AddressThis computer's LAN IP
Server PortADMS port (Settings → ADMS Server Info)
HTTPS / ProxyOFF
Never enter localhost or 127.0.0.1 on a device. Give this computer a fixed IP and allow port in its firewall.
3 TCP/IP (pull) Devices
1
Give the device a fixed IP (Menu → COMM → Ethernet). Default TCP port is 4370.
2
On Devices, use Network Ping Test, then Add TCP/IP Device. Enter the device's Comm Key (Menu → COMM → PC Connection) if it has one.
3
Punches are read automatically with every Attendance Push, or right away with Attendance → Fetch TCP or Sync Now.
4 ERP API

Your ERP needs three endpoints under the API Base URL. With a token set, requests send Authorization: Bearer <token>.

MethodPathPurpose
GET/zk/pingConnection test — any 2xx response
GET/zk/employeesEmployees for the devices
POST/zk/attendanceReceives punches

GET /zk/employees — response

{ "data": [
  { "uid": 1, "employee_id": "1001", "name": "Ayesha Rahman", "privilege": 0 }
] }

POST /zk/attendance — request body

{ "records": [
  { "employeeId": "1001", "time": "2026-10-10 08:42:04", "status": "0",
    "deviceId": "CQZ7224460123", "source": "adms", "verifyMethod": "fingerprint" }
] }
uidDevice user slot, 1–65535, unique per employee
employee_id / employeeIdThe ID employees use on the device
status0 Check-In, 1 Check-Out, 2 Break-Out, 3 Break-In, 4 OT-In, 5 OT-Out
timeDevice local time, YYYY-MM-DD HH:MM:SS
Reply with any 2xx status (optionally { "saved": 12 }). Otherwise the records stay New and are sent again next time — so ignore duplicates on employeeId + time + deviceId. Different paths? Enter full URLs in Settings → Fetch Employee URL / Sync Attendance URL.
5 Daily Use
Sync NowFetches from TCP/IP devices and pushes all new records to the ERP.
Employee SyncSettings → schedule: imports employees from the ERP and sends new ones to devices.
Attendance PushSettings → schedule: reads TCP/IP devices, then sends new records to the ERP.
Fetch ADMSAsks ADMS devices to upload punches stored before they were connected.
CSV / DATEmployee export for ZKTeco software or USB import.
6 Troubleshooting
ProblemCheck
Device not on the Devices pageServer address/port on the device, firewall, and that device and computer are on the same network (Ping Test). Restart the device and watch Logs for ADMS handshake.
Test Connection fails401/403: wrong token. 404: wrong base URL (include /api if your routes use it).
Records stay “New”Turn on Attendance Push, click Push to ERP and read the message and Logs.
Name not updated on deviceADMS devices apply changes on their next check-in (about 30 seconds).
